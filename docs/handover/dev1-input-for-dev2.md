## README.md: three paragraphs it must contain

**The corpus (§2).** RAHBAR answers from nine public FAST-NUCES documents: the 2026
Academic Rules Handbook and its superseded 2023 edition, the 2026 Student Handbook, the
Prospectus rules, two Annual Reports, the fee and grading pages, and a scanned start-ups
policy. The PDFs are not in this repository. `corpus/MANIFEST.md` records every URL and
SHA-256, and `python corpus/fetch.py` downloads the same files (with a pause between
requests). `python corpus/fetch.py --verify` checks the bytes. The indexer Job runs both
at start-up and refuses to index a file whose hash has changed. What each document is
for: `docs/CORPUS.md`.

**Models (§3.5).** Answers are generated by llama3.2:3b through Ollama on the host
(`LLM_PROVIDER=ollama-host`). Embeddings go through the same Ollama host with
nomic-embed-text: one `EMBED_MODEL` ConfigMap key is read by both the api and the
indexer. Ollama must listen on all interfaces (`OLLAMA_HOST=0.0.0.0 ollama serve`), with
both models pulled. `LLM_PROVIDER=hosted` is the one-file swap
(`api/app/providers/llm/hosted.py`, key from the Secret).

**Running it without a cluster** (checked on 2026-11-07, Windows with Docker Desktop):
```bash
docker run -d --name rahbar-chroma -p 8001:8000 -v rahbar-chroma-data:/data chromadb/chroma:1.0.12
docker run -d --name rahbar-redis -p 6379:6379 redis:7.4
python corpus/fetch.py
cd indexer && CORPUS_DIR=../corpus/raw CHROMA_HOST=localhost CHROMA_PORT=8001 \
  REDIS_HOST=localhost OLLAMA_URL=http://localhost:11434 python -m pipeline.run && cd ..
cd api && SERVE_UI_DIR=../ui RETRIEVER=chroma LLM_PROVIDER=ollama-host CACHE=redis \
  CHROMA_HOST=localhost CHROMA_PORT=8001 REDIS_HOST=localhost \
  OLLAMA_URL=http://localhost:11434 uvicorn app.main:app --port 8000
```
OCR needs tesseract on PATH. Open http://localhost:8000.

## ADR 0001 (indexer as a Job): facts from the indexer

- **What happens to the old index while the api serves from it** (store.py's own TODO
  asked for this in ADR 0001): a re-index upserts into the live collection and then deletes
  ids that no longer exist (`indexer/pipeline/store.py`, decision D15). The api keeps
  answering from the old chunks until the new ones land, and never sees an empty
  collection. Only a change of embedding model or dimension deletes and recreates the
  collection, and then the api is not-ready anyway, because of the pin.
- **The rejected alternatives for that:** delete and recreate on every run (an empty
  window that drops every pod's readiness), and a new collection per run swapped in by
  name (Chroma 1.0 has no alias, so the api would need to learn the new name).
- **Every run ends by expiring the semantic cache:** `INCR rahbar:cache:generation`
  (`indexer/pipeline/invalidate.py`). A Redis failure fails the Job, which retries.
  Re-running is safe because the store step is idempotent.
- **A run fails, rather than shrinking the index, when** a listed document yields zero
  chunks (`indexer/pipeline/run.py`), when a downloaded file's hash differs from MANIFEST,
  or when Ollama returns an error or a short batch (`indexer/pipeline/embed.py`).
- **Re-index without a redeploy:** `kubectl create job --from=cronjob/reindex manual-reindex-1 -n rahbar`.

## ADR 0004 (LLM provider and data governance): what leaves where

- **What the model sees:** the system instructions, at most TOP_K=5 retrieved passages from
  public FAST-NUCES documents, the user's question, and, for a conversation, the
  browser-sent summary and last HISTORY_TURNS turns (`api/app/services/prompt.py`,
  `conversation.py`). Nothing else: no ids, no request metadata.
- **Where it goes:** with `ollama-host`, to Ollama on the host machine. Nothing leaves the
  laptop. With `hosted`, the same prompt goes to the third-party endpoint in
  `HOSTED_BASE_URL`. The corpus is public; the question and history are user text, so the
  hosted mode is a data-sharing decision to state in the ADR.
- **What is stored:** no conversation server-side. History lives in the browser's
  localStorage (ADR 0002). The Redis cache stores the question's embedding (not its text)
  and the answer payload, only for safe standalone answers, and expires on re-index or
  after seven days (`api/app/providers/cache/semantic.py`).
- **What is logged:** at INFO, one line per request with ids, scores and flags, but not the
  question text. The prompt, history and rewritten query are logged at DEBUG only
  (`api/app/services/answer.py`). The ConfigMap must keep `LOG_LEVEL=INFO`.
- **Secrets:** `LLM_API_KEY` comes only from the Secret. It is excluded from the Settings
  repr and is never logged (`api/app/config.py`).
- **Model output is untrusted:** it is schema-validated, citations are checked against
  what was retrieved, and it is never executed or used to build a query or a path
  (`api/app/services/generation.py`).
